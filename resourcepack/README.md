# Resource pack — the shop menu art

This folder is **source** and is versioned. The packaged `.zip` is not: it is generated by
`./gradlew packZip`, which also computes the SHA-1 the client checks and copies the zip into the
plugin jar so the plugin can serve it itself.

**The pack is cosmetic.** The plugin never needs it to work. With
`config.yml → resource-pack.installed: false` every piece of art turns off at once and the menus
fall back to a plain chest with a text title — deliberately, because a player without the pack would
otherwise see missing-glyph boxes instead of a backdrop.

---

## How the backdrop works

The art is **not** a container texture. It is a glyph in a custom font, and the plugin puts that
glyph in the inventory's **title**. A title glyph renders *behind the items and in front of the
container background*, which is precisely the layer a menu backdrop needs, and it needs no client
mod and no NMS.

[`assets/minecraft/font/gui.json`](assets/minecraft/font/gui.json) declares two kinds of provider:

| Provider | What it gives us |
|---|---|
| `space` | `U+E9B0`–`U+E9BF` mapped to advances of ±1, 2, 4 … 128 px. Any pixel offset is a short combination of these, so the plugin can position the art horizontally. |
| `bitmap` | `U+E901` → `gui/garden_shop_gui.png` and `U+E902` → `gui/garden_shop_gui_list.png`, with `ascent` for the vertical position and `height` for the scale. |

`MenuBackground` in the plugin composes the offset characters and the glyph into the title.

### Why `ascent: 29` and `height: 256`

Both backdrops are a 256x256 canvas whose art occupies **x 2..253, y 0..238**.

The scale is 1:1, and that is measured rather than chosen. The art draws its own slot cells, and
those cells are **18 px apart** — the vanilla pitch. Scale the glyph at all and every item sits
off-centre in the cell drawn for it, which reads as bad art rather than as bad arithmetic.

With the scale fixed, both offsets fall out of two measurements:

| | drawn in the art | where the window puts it | shift |
|---|---|---|---|
| columns | x 47, 65, 83 … 191 | slots start at x 8 | 39 px left |
| rows | y 156, 174, 192, 214 | player rows at 140, 158, 176, 198 | 16 px up |

- A glyph's top row lands at `baseline - ascent`, and a title's baseline is y=13. Putting the canvas
  top at y=-16 needs `ascent = 13 + 16 = 29`.
- The title cursor starts at x=8, so putting the canvas left edge at x=-39 needs
  `background-x-offset: -47` in `gui.yml`.

The awning therefore overhangs the window by 16 px above, and the stand by ~37 px at each side. That
is how it was drawn: the window's bottom edge lands exactly on the art's.

This is why every menu is **6 rows**. The drawn grid is a 6-row chest's, so any other row count puts
the whole art in the wrong place.

### The icons, and why they are name tags

Four 16x16 textures in `textures/item/gardenshop/`, reached by CustomModelData:

| CustomModelData | texture | button |
|---|---|---|
| 74001 | `sell_select` | sell the held stack |
| 74002 | `sell_all` | sell everything |
| 74003 | `prices_book` | open the price book |
| 74004 | `user_info` | lifetime earnings |

They hang off `models/item/name_tag.json` and **not** `paper.json`, which matters: every item in the
crop pack is built on paper, so that pack ships its own `models/item/paper.json` with 144 overrides.
Two resource packs cannot both own one file — whichever loaded last would win and either the crops or
these icons would vanish. Name tags are nobody else's.

Each icon still declares a `fallback-material` in `gui.yml`, which is what a player without the pack
sees. A bare name tag would tell them nothing.

## Coexisting with other texture plugins

There is no Vault-style bridge for texture plugins — ItemsAdder, Nexo and Oraxen each have their own
API and no common one. None is needed here, because this pack is a **plain vanilla resource pack**:
a font provider and a PNG, with no plugin-specific metadata. Two ways to run it alongside another:

| | |
|---|---|
| **Stacked** (default) | Since 1.20.3 a client holds several packs at once. The plugin *adds* ours — `PackDelivery` sends `replace(false)` — so nothing another plugin delivered is evicted. Works with no configuration. |
| **Merged** | Point your existing pack merger at this folder, then set `resource-pack.enabled: false` and leave `installed: true`. The plugin stops delivering and just uses the glyphs. |

With **Nexo** the merged route needs no URL and no open port. Run `./gradlew packZip` and drop the
resulting `pack.zip` into `plugins/Nexo/pack/external_packs/` — Nexo
[merges it into the pack it already builds](https://docs.nexomc.com/configuration/resourcepack),
conflicting JSON included, and ships it through whatever hosting it is already using. Its default
`POLYMATH` type is Nexo's own free service, so there is nothing to host. ItemsAdder and Oraxen have
equivalent folders.

One caveat, and it applies only if you **stack**: our font is `minecraft:gui` — the file
`assets/minecraft/font/gui.json`. What Minecraft does when two packs define the same font id is not
documented, and whether providers are combined or the top pack's file wins outright has not been
verified here. Our codepoints (`U+E901`, `U+E9B0`–`U+E9BF`) can only collide with a pack that uses the
same font id, which most plugins do not: ItemsAdder, Nexo and Oraxen put their glyphs in
`minecraft:default`. Merging sidesteps the question entirely, because the merger resolves conflicting
files itself — which is a reason to prefer it when you have a pack manager anyway.

## Adding art

PNGs are binary, so drop them in yourself and the wiring is code-side.

| Kind | Where it goes | Size |
|---|---|---|
| Another menu backdrop | `textures/gui/<name>.png` | draw the slot cells at an 18px pitch, then measure |
| A button icon | `textures/item/gardenshop/<name>.png` | 16×16 |

**A new backdrop** needs a `bitmap` provider in `gui.json` on the next free codepoint (`U+E903`, …),
a constant in `GuiSettings`, a name in the loader's backdrop lookup, and its `ascent` worked out the
way the table above does it — from where the art draws its cells, not by eye.

**A button icon** needs a model at `models/item/gardenshop/<name>.json`, one more entry in
`models/item/name_tag.json`'s `overrides`, and that CustomModelData number written into the button's
`model-data` in `gui.yml`. Keep giving each one a `fallback-material`.

Do not move the icons onto `paper` for convenience. See above.

## Packaging

```powershell
.\gradlew packZip
```

Zips the **contents** of this folder — `pack.mcmeta` must sit at the zip root, not inside a
subfolder — prints the SHA-1, and embeds the result in the plugin jar.

Never edit the zip by hand. The client rejects a pack whose bytes do not match the SHA-1 the server
announced, and a hand-edited zip is the usual cause of "the pack won't download".

`pack_format: 32` with `supported_formats: 32..99` covers 1.20.6 through 1.21.x in one pack.

A `pack.png` (128×128, the pack's icon in the client's list) can be dropped at the root of this
folder whenever you have one; it is optional.
